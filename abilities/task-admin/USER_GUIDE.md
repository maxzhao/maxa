# task-admin 用户指南

`task-admin` 管理 `.maxa/tasks/` 下的单层任务工作区。每个任务拥有自己的实施方案、TODO、元数据和按需辅助文稿；任务之间只通过普通依赖表达顺序，不存在父任务或子任务。

## 1. 查看任务

示例：

- “查看当前 TaskAdmin 任务列表。”
- “列出 pending 和 in-progress 的任务。”
- “当前 tag 的下一个可执行任务是什么？”
- “查看任务 3 的实施方案和 TODO。”
- “找出依赖任务 4 的任务。”
- “列出没有依赖边的孤立任务。”

任务 ID 是 tag 内的整数，例如 `3`；不使用 `3.2` 形式。身份是 `tag + ID`，任务标题允许重复。只读查询可以指定其他 tag，不代表可以直接执行或修改其中的任务。

## 2. 创建任务

示例：

- “根据刚才的分析创建一个 TaskAdmin 任务，写完整实施方案和 TODO。”
- “创建高优先级任务：修复 MCPHub 重启后的状态丢失。”
- “创建任务 5，并让它依赖任务 3。”
- “这个需求包含两个独立交付物，请创建两个同层任务并设置依赖。”
- “明确创建一个探索任务，比较两种会话恢复方案；输出证据、结论和推荐方案，不实施。”

任务规划尚未执行的工作，不为已经完成的分析、规格编写、实施或验证补建记录。普通任务默认是实施任务：创建前只分析到足以确定范围、归属、方案、下一步和最小验收，不要求预先解决所有细节。TODO 包含可执行的修改和验证，不把开放研究交给下一个 Agent；简单任务不需要填满模板、编造方案对比或报告。

只有用户明确要求调查、研究、可行性验证或 spike 时，才创建探索任务；这类任务仍须明确问题、证据范围、停止条件和交付物。上下文不足的实施请求不会被 Agent 自行转换为探索任务。连续共享大量上下文的工作默认放在一个任务中。

## 3. 任务工作区

基础结构：

```text
task_NNN/
├── _meta.yaml
├── plan.md
└── todo.md
```

- `_meta.yaml`：名称、状态、优先级、依赖、时间和可选 workspace binding。
- `plan.md`：目标、范围、事实、方案、决策、风险、验收和验证计划。
- `todo.md`：执行清单、当前阶段、变更文件、验证、阻塞和下一步。
- 仅在用户或适用流程要求、现有 plan/TODO 无法承载必要上下文时增加辅助文稿；不为“完整性”额外写报告。模板中的空章节和重复记录可以省略。

示例：

- “解释任务 3 的元数据字段。”
- “在任务 3 中增加一份接口决策文稿，并从 plan/TODO 引用它。”
- “检查任务 3 的 plan 和 TODO 是否足够让新 Agent 接手。”

## 4. 执行或继续任务

示例：

- “执行 TaskAdmin 任务 5。”
- “继续当前任务，从第一个未完成 TODO 开始。”
- “执行下一个可执行任务。”
- “任务 7 做到哪里了？读取 TODO 后继续。”

执行、继续或编辑任务文稿前，先确认任务属于当前 tag；不匹配时停止，需要显式切换，不会自动切换。状态缺失或损坏时先修复当前 tag。随后读取 plan 和当前 TODO，在用户范围内完成最小充分实现、最小必要验证和状态更新后立即交付，不追加重构、测试轮次或文档润色。满足既定验收才标记 done；仍有必需的用户验收或验证缺口时使用 review 并说明，不虚报完成。普通“交付用户检查”不自动增加审批门槛。执行方式仍由你的明确要求和通用运行规则决定。

UI 展示和交互问题默认通过现有工具操作实际应用：观察问题、结合相关代码和现有日志定位、最小修复、复验受影响路径后交付。不会自行新增或修改单元/组件/E2E 测试、mock、夹具、测试辅助或临时诊断脚本；只有你明确要求编写/维护自动化测试，或适用强制验收规则明确要求这项工作时才允许。“验证一下”、风险和覆盖缺口都不是编写测试的授权。现有检查只作必要的有限补充，不替代实际交互；交互不可用则说明缺口，不通过造测试、示例应用或新环境冒充验证。完整测试仍仅在明确请求或强制验收要求时运行。

示例：“修复设置页保存问题，直接操作应用复现，修复后复验该路径并交付，不编写测试脚本。”

## 5. 更新任务状态和元数据

示例：

- “把任务 4 标记为 in-progress。”
- “把任务 4 标记为 review。”
- “验证和验收完成后，把任务 4 标记为 done。”
- “把任务 9 的优先级改成 high。”
- “更新任务 6 的名称或一句话描述。”
- “把任务 12 标记为 deferred，并保留 TODO 状态。”

元数据由脚本维护。普通创建、更新、删除、依赖修改、修复和重编号只作用于当前 tag，不能通过 `--tag` 绕过；操作其他 tag 前必须显式切换。已有存储状态异常时拒绝写入，不静默回退到 `master`；空存储首次创建仍初始化默认 tag。`done` 仍需要 Agent 检查 TODO、验收和验证；脚本不会仅通过解析 Markdown checkbox 判断完成。

## 6. 管理依赖

示例：

- “让任务 5 依赖任务 3。”
- “移除任务 5 对任务 3 的依赖。”
- “检查当前 tag 是否有缺失依赖或循环依赖。”
- “生成当前 tag 的依赖图。”

依赖只能指向同一 tag 中存在的整数任务；自依赖、重复、缺失和循环依赖会被拒绝。

## 7. 管理 tag

示例：

- “列出所有 TaskAdmin tag。”
- “创建 tag mvp。”
- “切换 active tag 到 mvp。”
- “把 master tag 复制成 experiment。”
- “把 old-name 重命名为 new-name。”
- “删除 tag experiment。”

Tag 保存任务集合和可选默认 workspace。`master` 是默认 tag，不能删除或重命名。

## 8. Workspace binding

示例：

- “把 tag mvp 绑定到 workspace feature-mvp。”
- “让任务 8 使用 workspace feature-auth。”
- “清除任务 8 的绑定，让它回退到 tag 默认值。”
- “查看任务 8 的 workspace 声明及其来源。”

有效顺序是任务值优先，其次 tag 默认。TaskAdmin 只读写声明性元数据，不检查路径、存在性或 checkout，不读取外部环境配置，也不会创建、切换或同步环境。外部调用方自行解释声明并实施其环境约束。

## 9. 删除、移动和重编号

示例：

- “删除任务 6；如果存在依赖先报告阻塞。”
- “强制删除任务 6，并移除指向它的依赖。”
- “把任务 8 移动到 backlog tag。”
- “把任务 7 重编号为 10。”
- “交换任务 4 和任务 9 的编号。”

跨 tag 移动固定从当前 tag 移出，显式选择目标，不改变当前 tag。移动会检查源 tag 的入边和目标 tag 是否存在所需依赖。强制模式只删除并报告无效依赖，不静默改指向其他任务。Tag 复制、重命名、删除等仍是显式集合管理操作；这些操作不授予其他 tag 的执行权限。

## 10. 合并不同 workspace 或分支中的任务

示例：

- “合并两个 workspace 的实现，并收敛其中同名的 TaskAdmin 任务。”
- “处理两个分支都创建了 task 5 的冲突，不要丢失 TODO 和依赖。”
- “检查两个任务是不是重复工作；重复则合并，否则保留并澄清名称。”

Agent 会在需要修改的 checkout 中逐个显式切换 tag，完成后恢复原 tag；以 `tag + 整数 ID` 判断任务身份，并结合 Git merge base、plan、TODO、验收条件、依赖和实现证据区分同一任务、ID 分配冲突、重复工作与仅同名的独立工作。Agent 负责重编号、语义合并、引用和依赖修复、重复任务删除及最终验证，不会把文件比较或冲突处理交给你。只有两个互斥的权威要求无法从仓库证据中裁决且会改变结果时，才会询问一个明确决策。

## 11. 与规格系统配合

TaskAdmin 本身不依赖规格系统。讨论、写入、修订或接受规格不自动创建任务；用户要求规划实施时，plan 引用相关规格并设计尚未执行的必要步骤。规格是任务的输入，不把“编写规格”当作实现规格。既有任务的 TODO 只维护必要执行状态和验收证据，不充当规格制定日志。

示例：

- “执行这个关联任务，先读 plan 中的 Spec References。”
- “检查任务 TODO、实现和关联规格是否已经收敛。”

## 12. 生命周期、压缩和恢复

示例：

- “按 TaskAdmin 流程执行任务 3，并维护生命周期状态。”
- “会话压缩后先恢复任务 plan、TODO、当前错误和下一步。”
- “更新 TODO，记录修改文件和验证结果。”

压缩与恢复会优先保留任务 ID/tag、plan 约束、当前 TODO、变更文件、阻塞、验证和下一步。

## 13. Vault 可见性

`.maxa/tasks/` 位于项目 Vault 中，但仍由 TaskAdmin 专用流程管理。不要把任务或 TODO 重复导出到知识目录，也不要自动把任务辅助文稿提升为长期知识。

## 你需要提供什么

- TaskAdmin 语境和动作：查看、创建、执行、继续、更新、删除、移动等。
- 整数任务 ID；不确定时可说“当前任务”或“下一个任务”。
- 只读查询可选 tag；普通写入请先选择当前 tag。
- 可选优先级、依赖、workspace 声明、验收或验证约束。
