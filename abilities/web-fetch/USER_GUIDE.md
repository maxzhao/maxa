# web-fetch 用户指南

web-fetch 用于让 Agent 通过统一本地入口完成网页搜索、已知 URL 抓取、正文提取、JS/反爬页面抓取、内容保存和正则片段提取。你只需要说明目标、网址或搜索词、期望输出；Agent 会选择合适模式，并在访问外网时按规则使用代理。

## 快速说法

- “用 web-fetch 搜一下 Neovim Lua autocmd 的官方文档。”
- “读取这个网页并转成 Markdown：https://example.com/article。”
- “抓取这个 URL，提取正文，不要导航和广告。”
- “这个页面需要 JS 渲染，用浏览器方式抓取。”
- “这个站反爬较强，尝试 stealth 抓取。”
- “把这个文件链接下载到 `/tmp/file.bin`。”
- “只提取页面里匹配 `Version [0-9.]+` 的上下文。”

## 场景 1：搜索后读取结果

适合没有确定 URL，只知道要找资料、新闻、库文档、issue 或解决方案。

示例：

- “搜索 `Neovim nvim_buf_set_text example`，读取最相关结果并总结。”
- “搜 `open-websearch supported engines`，整理前 5 个结果。”
- “用多个搜索源查 `Tauri WebDriverIO msedgedriver version match`。”
- “搜索报错 `ERR_MODULE_NOT_FOUND open-websearch`，优先看官方 issue 和文档。”

Agent 会使用结构化搜索结果选择候选 URL，再继续抓取页面。

## 场景 2：读取已知 URL

适合你已给网址，但不确定应该直接下载、提取正文还是走浏览器渲染。

示例：

- “读取这个 URL，输出 Markdown 摘要：https://example.com。”
- “打开这篇文章，提取主要内容，不要广告和侧栏。”
- “先用默认自动模式；失败再换其他方式。”
- “读取 GitHub 仓库页面，尽量拿 README 内容：https://github.com/neovim/neovim。”

自动模式会先识别特殊站点路由，再按通用方式尝试。

## 场景 3：直接访问或下载文件

适合 API、纯文本、JSON、HTML、二进制文件、压缩包、图片等需要保留原始内容的 URL。

示例：

- “直接抓取这个 JSON API，保留原始响应。”
- “下载这个二进制文件到 `/tmp/model.bin`，已存在就覆盖。”
- “把这个 HTML 原样保存到 `/tmp/page.html`。”
- “这个链接不要做正文提取，直接拿 HTTP 响应。”

二进制内容不能安全内联时，Agent 会保存文件或改用 Markdown 转换。

## 场景 4：提取网页正文

适合普通文章、博客、文档页、新闻页，需要去掉导航、侧栏、广告等噪声。

示例：

- “提取这篇博客正文，转成 Markdown。”
- “读取这个文档页，只保留正文和标题层级。”
- “这个网页直接抓取很乱，用可读正文提取。”
- “提取文章后总结关键 API。”

## 场景 5：JS 渲染页面

适合直接 HTTP 获取为空、内容由前端动态渲染、需要浏览器环境才能看到正文的页面。

示例：

- “这个页面是 JS 渲染的，用浏览器方式抓取。”
- “直接抓取只有空壳 HTML，换 browser 模式。”
- “抓这个动态文档页，保留渲染后的 HTML/Markdown。”

如果本机缺少浏览器或相关依赖，Agent 会报告依赖问题，并按情况降级或说明阻塞原因。

## 场景 6：强反爬页面

适合普通请求和浏览器模式都失败、页面有挑战页或访问限制的情况。

示例：

- “这个站有反爬，尝试 stealth 抓取。”
- “普通读取返回挑战页，用更强的反爬模式。”
- “如果 direct/readable 都失败，再尝试 stealth，并说明失败点。”

stealth 是最后升级尝试，仍可能受本机依赖或站点策略限制。

## 场景 7：只提取匹配片段

适合页面很长，只关心版本号、错误码、函数名、配置项或关键词附近上下文。

示例：

- “读取这个页面，只提取包含 `Version [0-9.]+` 的上下文。”
- “找 `nvim_create_autocmd` 附近 300 个字符。”
- “搜索 `ERROR_CODE_[A-Z_]+`，输出匹配片段，不要全文。”
- “这个 GitHub URL 不要走特殊 README 路由，按普通网页匹配 `Installation`。”

正则作用于最终格式化后的文本；无匹配会明确失败。特殊站点路由不支持正则，Agent 会禁用特殊路由或改用普通模式。

## 场景 8：保存或转换内容

适合把网页、API 响应或下载内容留到本地文件继续分析。

示例：

- “把这个网页转换成 Markdown 保存到 `/tmp/article.md`。”
- “把原始响应保存到 `/tmp/response.txt`，不要摘要。”
- “下载这个链接，限制最大 10MB，保存到指定路径。”
- “如果目标文件存在，请覆盖写入。”

支持 raw/markdown 输出、内联或写文件、覆盖控制、最大字节数限制。Markdown 转换失败时，Agent 会保留错误并可改用 raw 保存。

## 场景 9：代理、超时和访问限制

适合访问外网、网络慢、站点限制地区访问或需要明确代理。

示例：

- “通过代理读取这个国外网页。”
- “这个页面响应很慢，把超时调到 120 秒。”
- “访问外网时使用代理 `http://127.0.0.1:10808`。”
- “限制最多读取 2MB，避免输出太大。”

## 场景 10：维护 web-fetch 技能

适合排查 CLI、依赖、抓取失败或回归测试。

示例：

- “检查 web-fetch 的 CLI 帮助和支持的子命令。”
- “跑 web-fetch 的本地 smoke 测试，不要访问真实外网。”
- “验证 auto 路由、输出文件、正则提取和旧命令移除。”
- “排查 readable 模式失败，检查 open-websearch 适配器和依赖状态。”
- “检查 browser/stealth 依赖缺失时错误是否清晰。”

## 能力概览

- 统一命令入口：搜索和 URL 抓取都由本地 `web-fetch` 命令完成。
- CLI 规格：公开子命令、参数、输出、错误、特殊路由和验证命令。
- 实现能力：自动路由、直接访问、正文提取、browser/stealth 动态抓取、搜索桥接、输出/正则处理。
- 测试资源：覆盖自动路由、输出模型、正则提取、文件输出、错误路径、旧命令移除、搜索和 readable 适配器。
- vendored 资源：复用 open-websearch、mcp-server-fetch、scrapling-fetch-mcp 能力，但不要求用户掌握内部路径。

## 不确定怎么问

- “判断这个网页需求是否适合用 web-fetch，并选择最稳的抓取方式。”
- “先搜索，再读取最相关结果，最后给我总结和来源链接。”
- “这个 URL 抓取失败时，请按 direct/readable/browser/stealth 逐步处理，并说明失败点。”
